# 知识共享系统需求规格说明书

## 1. 引言

本说明书定义知识共享系统 JavaWeb 后端的接口需求及可验证验收准则。基础地址为 `http://localhost:8080/knowledge_sharing_system`，接口统一返回 JSON：`flag` 表示 success/fail，`data` 承载业务数据或提示。

## 2. 总体描述

角色：游客可注册、登录、浏览已审核知识；普通用户可维护个人资料、发布/删除自己的知识、收藏；管理员可审核知识并管理用户。主流程：注册→登录→浏览/收藏→发布（待审核）→管理员审核→公开展示。

## 3. 功能需求与验收标准

### 3.1 用户模块

注册必须校验用户名非空、密码至少 6 位、两次密码一致，用户名/邮箱/手机任一重复均返回 `flag=fail`；成功创建普通用户并返回 success。登录支持用户名、邮箱或手机号；账号、密码为空或错误均失败；禁用账号必须拒绝登录。登录成功后建立 Session，返回用户 id、用户名、角色；退出后受保护接口必须提示先登录。修改资料仅允许登录用户修改本人邮箱和手机号；修改密码需原密码正确、新密码不少于 6 位。

⚠️ 注意：当前 `UserDao.login` 未过滤 `status=0`，禁用的陈小明实际可登录，和需求不符。

### 3.2 知识模块

公开列表只能返回 `status=1` 且未逻辑删除的知识。详情只能公开已审核通过内容；不存在、非数字或未审核 ID 均应返回失败 JSON。登录用户可发布非空标题和内容，初始状态必须为待审核；“我的知识”仅返回本人记录。用户只能删除本人知识，管理员可删除任意知识；删除应设置 `is_deleted=1`，且列表、详情、收藏查询均不得展示。

⚠️ 注意：当前 DAO 使用物理 `DELETE`，未实现 `is_deleted` 逻辑删除；`findById` 未限制 `status=1`，待审核/拒绝内容可通过 ID 泄露。

### 3.3 收藏模块

仅登录用户可收藏已审核、存在的知识；重复收藏应失败且不新增记录。已收藏时取消成功；从未收藏时取消必须失败并说明原因；我的收藏只显示存在、已审核、未删除知识。

⚠️ 注意：当前取消收藏忽略 Service 返回值，未收藏也返回“取消收藏成功”。

### 3.4 管理员模块

普通用户/游客访问管理员接口必须失败。管理员待审核列表仅含待审核且未删除知识；审核动作仅接受 `approve` 或 `reject`，并更新到 1/2。管理员可查看非删除用户，修改用户时用户名、邮箱、手机号必须非空且不能与其他用户冲突；管理员不能删除自己，删除用户应逻辑删除。

⚠️ 注意：当前管理员修改未先校验唯一性，仅由数据库异常返回笼统失败；非法 `auditAction` 会被误当成拒绝。

## 4. 非功能需求

- 所有业务异常均返回 HTTP 可解析 JSON，不得将 NumberFormatException/SQL 异常泄露给调用方。
- 使用参数化 SQL 防 SQL 注入；输出内容应进行 XSS 编码或过滤。
- 密码不得明文存储、传输建议启用 HTTPS；会话退出后立即失效。
- 权限判断必须在服务端完成；接口响应使用 UTF-8，数据库为 MySQL `knowledge_share:3306`。

|用户|POST|/register|username,password,confirmPassword,email,phone|公开|
|用户|POST|/login|username,password|公开|
|用户|GET|/logout|-|登录|
|用户|POST|/user|action=updateInfo/updatePassword|本人|
|知识|GET|/knowledge|action=list/detail/myKnowledge/pending|按 action|
|知识|POST|/knowledge|action=publish/delete/adminDelete/audit|按 action|
|收藏|GET/POST|/knowledge|action=myFavorites/favorite|登录|
|管理员|GET/POST|/admin/user|action=update/delete|管理员|
