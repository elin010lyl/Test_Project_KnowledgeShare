# 知识共享后台系统 测试计划（项目概述 + 测试环境 + 测试范围）

> 文档版本：V1.0　|　编写人：测试组　|　日期：2026-09-20　|　项目代号：KSS（Knowledge Sharing System）

## 1. 项目概述

### 1.1 项目背景
知识共享后台系统是一个面向校园/企业内部的知识管理平台后端服务。普通用户可以注册登录后发布知识文章（发布后需管理员审核），浏览已审核通过的知识，收藏感兴趣的知识并维护个人信息；管理员负责知识内容的审核（通过/拒绝）、删除违规知识以及用户信息的管理。本次迭代为该系统的**第一版正式发布（V1.0）**，测试组需对其全部 **21 个 HTTP JSON 接口**完成功能测试与接口自动化测试，并输出整套测试交付物。

### 1.2 系统架构与技术栈
| 层次 | 技术 | 说明 |
|---|---|---|
| Web容器 | Apache Tomcat 9.x | 部署 war 包，上下文路径 `/knowledge_sharing_system` |
| 开发框架 | Java Servlet（javax.servlet）+ fastjson 1.2.66 | 无前端页面，纯后端 JSON 接口 |
| 数据库 | MySQL 8.x，库名 `knowledge_share` | 表：users、knowledge、favorite |
| 持久层 | JDBC（DBHelper 工具类封装） | PreparedStatement 预编译防注入 |
| 鉴权方式 | HttpSession + Cookie（JSESSIONID） | 登录成功后 Session 写入 userId/username/role |
| 数据格式 | 请求：URL 参数（Query String）；响应：JSON `{"flag": "success/fail", "data": ...}` | 编码 UTF-8 |

### 1.3 角色与核心业务
| 角色 | role 值 | 权限 |
|---|---|---|
| 游客（未登录） | - | 注册、登录；浏览知识列表/详情 |
| 普通用户 | 0 | 发布知识（进入待审核）、查看我的发布、删除自己的知识、收藏/取消收藏/我的收藏、修改个人信息、修改密码、退出登录 |
| 管理员 | 1 | 普通用户全部权限 + 查看待审核知识、审核通过/拒绝、删除任意知识、查看所有用户、修改/删除用户（不能删除自己） |

**核心业务流程**：
1. 注册 → 登录（用户名/邮箱/手机号三选一）→ 发布知识（状态=待审核）→ 管理员审核（通过后进入公开列表）→ 其他用户浏览/收藏。
2. 用户中心：修改邮箱/手机号、修改密码（旧密码校验、新密码≥6位）。
3. 管理端：待审核列表 → 通过/拒绝 → 删除知识（级联删除收藏记录）；用户管理 → 修改/删除用户（级联删除该用户的知识与收藏）。

### 1.4 数据字典（核心字段）
| 对象 | 字段 | 说明 |
|---|---|---|
| users | id, username, password, email, phone, role | role：0=普通用户，1=管理员 |
| knowledge | id, title, content, category, user_id, status, view_count, create_time | status：0=待审核，1=已通过，2=未通过 |
| favorite | id, user_id, knowledge_id, create_time | 用户-知识 收藏关系表 |

## 3. 测试范围

### 3.1 本期测试范围（In Scope）
| 模块 | 接口数 | 内容 |
|---|---|---|
| 用户注册 | 1 | 注册参数校验（非空/长度/两次密码一致/用户名-邮箱-手机号唯一性） |
| 用户登录/登出 | 2 | 用户名/邮箱/手机号三种登录、错误口令、Session 建立、登出销毁会话 |
| 知识浏览 | 2 | 已审核知识列表（含发布人、倒序）、详情（浏览量+1） |
| 知识发布/管理 | 3 | 发布（进入待审核）、我的发布、删除自己的知识（仅限本人） |
| 知识收藏 | 3 | 收藏、重复收藏拦截、取消收藏、我的收藏（仅显示已审核通过） |
| 个人信息 | 2 | 修改邮箱/手机号、修改密码（旧密码校验、新密码≥6位） |
| 管理员-知识审核 | 5 | 待审核列表、审核通过/拒绝、管理员删除知识（级联删收藏） |
| 管理员-用户管理 | 3 | 所有用户列表、修改用户信息、删除用户（级联删该用户知识与收藏、不能删除自己） |
| 通用校验 | - | 鉴权（未登录/角色越权）、未知 action、HTTP 状态码、JSON 结构一致性 |

### 3.2 非本期范围（Out of Scope）
- 前端页面/UI 测试（本系统为纯后端接口，无页面）。
- 性能/压力测试、安全渗透测试（本期仅做基础安全项检查：鉴权、越权、SQL 注入、敏感信息泄露）。
- 数据库主从、缓存等部署架构类测试。

### 3.3 测试重点与难点
1. **鉴权与越权**：全部"需登录/需管理员"接口的 Session 校验，普通用户调用管理员接口必须返回"无权限"。
2. **数据级联一致性**：删除知识/删除用户时 favorite 记录级联清理，不产生孤儿数据。
3. **状态机正确性**：知识状态流转（待审核→通过/拒绝），公开列表只出 status=1 数据。
4. **异常输入**：非数字 ID、空参数、超长文本、特殊字符、SQL 注入探测。

## 4. 测试策略与流程

### 4.1 测试类型
| 类型 | 方式 | 说明 |
|---|---|---|
| 手工功能测试 | Postman + Excel 用例 | 按模块设计用例，逐条执行，记录实际结果 |
| 接口自动化测试 | pytest + requests + allure | 核心正/反向场景自动化，回归执行 |
| 冒烟测试 | 每轮执行 | 覆盖注册→登录→发布→审核→浏览主链路 |

### 4.2 测试流程
需求/接口文档评审 → 测试点分析 → 用例设计与评审 → 冒烟 → 第一轮系统测试（缺陷提交禅道）→ 开发修复 → 回归测试 → 第二轮全量回归 → 输出测试报告 → 发布评审。

### 4.3 准入/准出标准
**准入**：代码提测、数据库脚本就绪、冒烟用例 100% 通过、主流程无阻塞缺陷。
**准出**：用例执行率 100%，通过率 ≥ 95%，无未解决的一级/二级缺陷，遗留缺陷经评审同意带缺陷发布。

## 6. 风险与应对
| 风险 | 影响 | 应对措施 |
|---|---|---|
| 接口文档与实际实现不一致（如异常提示文案） | 用例预期结果偏差 | 以实际响应为准记录，差异提缺陷由产品确认 |
| 测试数据被其他成员修改 | 用例误报 | 用例数据使用独立账号/唯一前缀，用后清理 |
| 部分接口未返回业务主键（如发布成功不返回知识ID） | 自动化断言链路受阻 | 通过"我的发布"列表反查最新记录获取 ID |
| 环境不可用（Tomcat/MySQL 未启动） | 执行阻塞 | 执行前冒烟检查，环境问题即时反馈 |
