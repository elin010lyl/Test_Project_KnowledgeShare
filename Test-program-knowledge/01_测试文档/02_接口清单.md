# 知识共享后台系统 接口清单（21 个）

> 基准地址：`http://localhost:8080/knowledge_sharing_system`
> 统一响应格式：JSON `{"flag": "success|fail", "data": 字符串|对象|数组}`
> 鉴权说明：登录成功后服务端建立 Session，客户端凭 Cookie（JSESSIONID）维持会话；标注"需登录/需管理员"的接口在未满足条件时返回 `{"flag":"fail","data":"请先登录"}` 或 `{"flag":"fail","data":"无权限"}`。

## 模块一：用户注册/登录/登出（3 个）

### 1. 用户注册 POST /register
| 项目 | 说明 |
|---|---|
| 参数 | username、password、confirmPassword、email、phone |
| 业务规则 | ① username 非空（trim 判断）② password 长度≥6 ③ password=confirmPassword ④ username/email/phone 唯一，重复返回"用户名或邮箱或手机号已被注册"；新用户 role=0 |
| 成功响应 | `{"flag":"success","data":"注册成功"}` |
| 备注 | doGet 转发 doPost，即 GET 也可注册（已提安全缺陷） |

### 2. 用户登录 POST /login
| 项目 | 说明 |
|---|---|
| 参数 | username（支持用户名/邮箱/手机号三选一）、password |
| 业务规则 | 参数非空校验；SQL 按 `(username=? OR email=? OR phone=?) AND password=?` 匹配；成功后 Session 写入 userId/username/role |
| 成功响应 | `{"flag":"success","data":{"id":2,"username":"testuser1","role":0}}` |
| 失败响应 | `{"flag":"fail","data":"用户名或密码错误"}` / `...不能为空` |

### 3. 退出登录 GET /logout
| 项目 | 说明 |
|---|---|
| 参数 | 无 |
| 业务规则 | `session.invalidate()` 销毁会话 |
| 成功响应 | `{"flag":"success","data":"退出成功"}` |

## 模块二：知识浏览（2 个）

### 4. 查看知识列表 GET /knowledge?action=list
| 项目 | 说明 |
|---|---|
| 鉴权 | 无需登录 |
| 业务规则 | 仅返回 status=1（审核通过）的知识，按 create_time 倒序，含 publisher_name（LEFT JOIN users） |
| 成功响应 | data 为数组，元素字段：id/title/content/category/userId/status/viewCount/createTime/publisherName |

### 5. 查看知识详情 GET /knowledge?action=detail&id=1
| 项目 | 说明 |
|---|---|
| 鉴权 | 无需登录 |
| 业务规则 | id 非空；命中返回详情且 **view_count 自增 1**；未命中返回"知识不存在" |
| 失败响应 | id 缺失：`"知识ID不能为空"`；不存在：`"知识不存在"` |
| 缺陷备注 | id 传非数字（如 abc）触发 NumberFormatException，HTTP 500（已提缺陷 BUG-002） |

## 模块三：知识发布与管理（3 个，均需登录）

### 6. 发布知识 POST /knowledge?action=publish
| 项目 | 说明 |
|---|---|
| 参数 | title、content、category（可空，不影响提交） |
| 业务规则 | title 非空、content 非空；新知识 status=0（待审核）、view_count=0 |
| 成功响应 | `{"flag":"success","data":"发布成功，等待审核"}` |

### 7. 查看我发布的知识 GET /knowledge?action=myKnowledge
| 业务规则 | 按 Session userId 过滤，create_time 倒序；含待审核/通过/拒绝全部状态 |

### 8. 删除自己发布的知识 POST /knowledge?action=delete&id=16
| 业务规则 | 校验归属（isOwner）：仅能删除 user_id=自己 的知识；非本人返回"只能删除自己发布的知识"；删除时级联删除该知识的收藏记录 |

## 模块四：知识收藏（3 个，均需登录）

### 9. 收藏知识 POST /knowledge?action=favorite&favAction=add&knowledgeId=1
| 业务规则 | knowledgeId 非空；favAction=add 时若已收藏返回"已经收藏过了"；未收藏则插入 favorite 记录返回"收藏成功" |
| 缺陷备注 | 不校验知识是否存在，可收藏不存在的 knowledgeId（BUG-003） |

### 10. 取消收藏 POST /knowledge?action=favorite&favAction=remove&knowledgeId=1
| 业务规则 | 删除 favorite 记录，无论是否存在记录均返回"取消收藏成功"（幂等） |

### 11. 查看我的收藏 GET /knowledge?action=myFavorites
| 业务规则 | 返回该用户收藏的知识中 **status=1（已审核通过）** 的部分 |

## 模块五：个人信息维护（2 个，均需登录）

### 12. 修改个人信息 POST /user?action=updateInfo&email=newemail@qq.com&phone=13999999999
| 业务规则 | 按 Session userId 更新 email/phone；返回"修改成功/修改失败" |
| 缺陷备注 | 无邮箱/手机号格式校验；邮箱与他人重复时因唯一约束失败仅提示"修改失败"（BUG-006） |

### 13. 修改密码 POST /user?action=updatePassword&oldPassword=123456&newPassword=654321
| 业务规则 | 新密码非空且长度≥6；校验旧密码正确（明文比对）后更新 |
| 失败响应 | `"新密码长度不能少于6位"` / `"原密码错误"` |

## 模块六：管理员-知识审核（4 个，均需管理员 role=1）

### 14. 管理员登录 POST /login（复用接口2，admin/admin123，role=1）
### 15. 查看待审核知识 GET /knowledge?action=pending
| 业务规则 | 返回 status=0 的知识列表，倒序 |

### 16. 审核通过 POST /knowledge?action=audit&id=11&auditAction=approve
### 17. 审核拒绝 POST /knowledge?action=audit&id=12&auditAction=reject
| 业务规则（合并16/17） | auditAction=approve → status=1"审核通过"；其余值 → status=2"审核拒绝"；成功/失败分别返回 |
| 缺陷备注 | auditAction 传非法值（如 approv）也按"拒绝"处理（BUG-004）；不校验知识当前状态，可重复审核（BUG-005） |

### 18. 管理员删除知识 POST /knowledge?action=adminDelete&id=1
| 业务规则 | 物理删除任意状态的知识，级联删除其收藏记录 |

## 模块七：管理员-用户管理（3 个，均需管理员 role=1）

### 19. 查看所有用户 GET /admin/user
| 业务规则 | 返回全部用户：id/username/email/phone/role（不含密码） |

### 20. 管理员修改用户信息 POST /admin/user?action=update&id=2&username=张三新名字&email=newzhangsan@qq.com&phone=13900000000
| 业务规则 | id 非空；更新 username/email/phone；命中返回"修改成功"，未命中/异常返回"修改失败" |
| 缺陷备注 | username 改成与已有用户重复时触发唯一约束异常，仅提示"修改失败"（BUG-008） |

### 21. 管理员删除用户 POST /admin/user?action=delete&id=5
| 业务规则 | 不能删除自己（返回"不能删除自己"）；删除用户前级联删除其全部收藏、其发布的全部知识（含对应收藏） |

## 附：鉴权/异常统一行为（各接口通用测试点）
| 场景 | 预期 |
|---|---|
| 需登录接口未携带 Session 调用 | `{"flag":"fail","data":"请先登录"}` |
| 普通用户调用管理员接口（pending/audit/adminDelete/admin/user） | `{"flag":"fail","data":"无权限"}` |
| knowledge/user 接口传未定义的 action | `{"flag":"fail","data":"未知操作"}` |
| knowledge POST 未带 action | 同上"未知操作" |
