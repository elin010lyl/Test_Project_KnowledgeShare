## BUG-001 注册/修改个人信息接口未校验邮箱与手机号格式

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-001 |
| 所属模块 | 用户注册 / 个人信息 |
| 影响版本 | V1.0（提测版本） |
| 缺陷类型 | 功能逻辑-校验缺失 |
| 严重程度 | 一般 |
| 优先级 | P2 |
| 复现概率 | 必现 |
| 状态 | 已关闭 |
| 解决方案 | 修改-服务端已增加邮箱正则与手机号11位校验 |

**重现步骤**：
1. Postman 调用 `POST /register`，email 传非法格式 `abcdefg`，其余参数合法；
2. 发送请求，观察响应；
3. 调用 `POST /user?action=updateInfo`，email 传 `not-an-email`，同样发送。

**预期结果**：提示"邮箱格式错误"（或对应手机号提示），注册/修改失败，数据库不写入非法数据。
**实际结果**：两个接口均返回 `{"flag":"success"}`，非法格式邮箱、手机号成功入库。
**关联用例**：KSS-REG-010、KSS-REG-011、KSS-INFO-004
**备注**：非法手机号入库后用户无法收到短信通知，且污染数据。

## BUG-002 接口传入非数字ID时服务端500异常

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-002 |
| 所属模块 | 知识详情/删除/收藏/审核/管理员用户管理（多接口共性） |
| 影响版本 | V1.0 |
| 缺陷类型 | 代码错误-异常未捕获 |
| 严重程度 | 严重 |
| 优先级 | P2 |
| 复现概率 | 必现 |
| 状态 | 已关闭 |
| 解决方案 | 修改-统一增加参数校验与异常处理，非法ID返回flag=fail |

**重现步骤**：
1. 登录普通用户，调用 `GET /knowledge?action=detail&id=abc`；
2. 同法验证 `POST /knowledge?action=delete&id=abc`、`POST /knowledge?action=adminDelete&id=abc`、`POST /admin/user?action=update&id=abc`、`POST /admin/user?action=delete&id=abc`；
3. 检查 HTTP 状态码与 Tomcat 日志。

**预期结果**：参数校验失败，返回 `{"flag":"fail","data":"知识ID格式错误"}` 类业务提示，HTTP 状态码 200。
**实际结果**：服务端 `Long.parseLong()` 抛出 `NumberFormatException` 未捕获，返回 HTTP 500，Tomcat 打印堆栈，接口无业务提示。
**关联用例**：KSS-DTL-005、KSS-DEL-006、KSS-ADEL-005、KSS-AUU-006、KSS-AUD-005
**备注**：500 响应包含服务器异常堆栈信息，存在信息泄露风险；建议统一封装参数解析工具方法。

## BUG-004 审核接口 auditAction 传非法值时默认按"拒绝"处理

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-004 |
| 所属模块 | 管理员-知识审核 |
| 影响版本 | V1.0 |
| 缺陷类型 | 功能逻辑-默认分支错误 |
| 严重程度 | 一般 |
| 优先级 | P3 |
| 复现概率 | 必现 |
| 状态 | 已关闭 |
| 解决方案 | 修改-auditAction 仅接受 approve/reject，其余值报参数错误 |

**重现步骤**：
1. 管理员登录；
2. 调用 `POST /knowledge?action=audit&id=13&auditAction=approv`（故意拼写错误）；
3. 查询该知识 status。

**预期结果**：提示"操作类型错误"，知识状态保持待审核不变。
**实际结果**：代码逻辑为 `int status = "approve".equals(auditAction) ? 1 : 2;`，非 approve 一律置为 2（拒绝），知识被误拒下架。
**关联用例**：KSS-AUDIT-005
**备注**：前端若传错参数会导致内容被误拒，属于危险默认值设计。

## BUG-005 审核接口未校验知识当前状态，已通过知识可被重复审核

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-005 |
| 所属模块 | 管理员-知识审核 |
| 影响版本 | V1.0 |
| 缺陷类型 | 功能逻辑-状态机缺失 |
| 严重程度 | 轻微 |
| 优先级 | P3 |
| 复现概率 | 必现 |
| 状态 | 已关闭 |
| 解决方案 | 修改-仅 status=0 的知识允许审核，终态知识返回审核失败 |

**重现步骤**：
1. 管理员登录；
2. 调用 `POST /knowledge?action=audit&id=1&auditAction=reject`（id=1 已是审核通过状态）；

**预期结果**：提示"该知识已审核，不允许重复审核"，公开列表内容不受影响。
**实际结果**：审核"拒绝"成功，已公开发布的知识被直接下架。
**关联用例**：KSS-AUDIT-006

## BUG-007 注册/登录等敏感接口未限制请求方法，GET 可提交

| 字段 | 内容 |
|---|---|
| 缺陷编号 | BUG-007 |
| 所属模块 | 注册/登录（通用安全） |
| 影响版本 | V1.0 |
| 缺陷类型 | 安全漏洞 |
| 严重程度 | 严重 |
| 优先级 | P2 |
| 复现概率 | 必现 |
| 状态 | 已关闭 |
| 解决方案 | 修改-写操作接口仅接受 POST，GET 直接拒绝 |

**重现步骤**：
1. 浏览器地址栏直接输入 `GET /register?username=getreg001&password=123456&...`；
2. 同法访问 `GET /login?username=testuser1&password=123456`；
3. 观察响应与数据库。

**预期结果**：GET 方式访问写接口返回 405 或业务错误，敏感操作仅允许 POST。
**实际结果**：Servlet 的 doGet 直接转发 doPost，GET 方式注册、登录全部成功；账号密码出现在 URL、浏览器历史与服务器 access log 中，存在敏感信息泄露风险。
**关联用例**：KSS-REG-012、KSS-LOGIN-010
